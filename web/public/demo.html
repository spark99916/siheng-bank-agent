探针是进程概念：这一页自带引擎、没有独立进程，所以不显示 —— 不摆三个假 200 出来。 右侧读数（状态、审计链、幂等、工单）仍然来自同一份代码，不受影响。 本机若正好跑着那个进程，加 ?live=1 打开本页就能看到真探针与磁盘审计；不起也不影响上面这些读数。

两个探针不合并：合成一个的后果是优雅退出时探针失败，调度重启一个正在正常退出的进程，永远退不干净。/ready 有三种情况会 503 并写明原因：正在退出、状态文件读坏回落初始值、落盘目录写不进去。

最近六个版本

每一条都不是加功能，是堵一个真能出事的缝

v1.12.1

不能转给自己

「我自己」「本人」「林知远」都曾能出确认卡、确认后真扣钱。转给自己不产生资金流动，却占掉日累计、频次与首次收款人额度 —— 改判红，且不给确认。

v1.13.0

判定搬进页面

把 agent.ts 与 shared/ 原样编译进这一页，只换 crypto / fs / path / os 四层 I/O。判定、审计链、令牌、幂等仍是同一份代码，持久层换成内存。

v1.14.0

打开即用，默认就在本地

不再「先试一下、连不上才回落」：开机直接跑页内引擎，一个网络请求都不发。业务界面 / 同样收成单文件，双击也能办业务。?live=1 才去打真进程。

v1.14.1

页面上不再教人开机

行为早就是本地跑，文案却还在写「先到命令行起个服务」。凡是打开就能用的东西，页面上不出现任何启动或连接指令 —— 这一条现在写进了验收。

v1.14.2

问人要像在问人

先说「转 100 元」被回「还差转给谁」，再说「我自己」被回「没听懂」。改成「请问这笔转给谁呢」；整句自称先认下来，才轮得到「转给自己不成立」这句话说出口。

v1.15.0

沿用上次收款人，但要说得明白

只说金额时仍沿用，可卡上必须写清：这不是你说的、我按哪一笔补的（带上次的金额与时间）、要改怎么说。记忆 30 天过期；你一改口，上一张卡立刻作废。

v1.16.0

接着说这个人

刚说「转给阿杰」、下一句只说金额，系统不再从头问「转给谁」，而是问一句「还是转给阿杰吗」。只跟同一会话、15 分钟内有效；答「是」才开卡，答「不是」或直接说个新名字，都当场改。

边界

四处现在还不成立的地方

主动写出来，比被评委问出来强。前两条在真上线前必须收口。

位置现状状态
信任边界

主体档位 tier 与阈值覆盖仍由客户端声明，服务端只校验格式、不校验授权。会改参数的人可以把自己说成私行、把红线拉满。演示要切档位是对的诉求，实现方式错了。

未收口
多副本

幂等编号、工单号、在途计数都在单进程内。请求打到 B 实例，A 实例办过它也看不见。单副本下钱是安全的（检查与动账之间没有 await 点）。

单实例有效
工单鉴权

handoffs / handoff.claim / handoff.close 没有鉴权 —— 谁连得上端口，谁就能把一张 P0 工单点成结案。这比没有工单更坏，因为它给了个「有人办过」的假象。

内网可接受
两写窗口

state 已写、audit 未写之间进程被杀，审计链仍然报完整：hash 链只防篡改，不防截断。要做就得把两次写并进一个事务，赛前不动。

未做

另外，这一页默认跑的是页内引擎：判定与审计是同一份代码，但持久层是内存、不调模型、不连外部反欺诈。它是演示形态，不是产品形态 —— 所以那一屏上没有探针，也不会假装有。
